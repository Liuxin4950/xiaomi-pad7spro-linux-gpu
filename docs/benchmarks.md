# 功耗、流畅度和稳定性测试

当前版本 r3.3，最新配置及范围见 [CURRENT-STATE](CURRENT-STATE.md)，原生二维实测见 [交付报告](r3.3-native-rendering.md)。下文早期数据保留其日期，不作为新版本功耗结论。

默认基线为原生分辨率、60 FPS。把“GPU 能用”“画面正确”“功耗更低”“续航更长”分开验证。

## 已有数据的使用范围

作者曾观察 CPU 渲染时约 7–11 W。设备文档还保存了 2026-09-16/17 的 llvmpipe/Zink 功耗和帧率数字。这些记录并未统一到当前应用、X11 补丁与 60 FPS 配置，因此不作为新版同任务对照，也不计算节能比例或续航倍数。

Termux:X11 既有记录测得大窗口约 118.4 次 Present/秒。60 FPS 会降低呈现次数与像素搬运压力，但整机功耗还受驱动、CPU、亮度、温度和实际负载影响。不能把呈现压力减半说成整机功耗减半。

## 对照设计

首轮比较 **CPU 60 FPS 与 GPU 60 FPS**，并保持亮度、分辨率、页面/项目、操作节奏和软件版本一致。再单独比较 **GPU 60 FPS 与 GPU 120 FPS**，衡量限帧的作用。这样才能区分驱动加速和限帧的收益。

| 条件 | 应记录的内容 |
|---|---|
| 硬件/软件 | 设备、固件、root 方式、容器、应用、Mesa、桥接和 X11 版本/哈希 |
| 显示 | Android 亮度、面板刷新率、X11 分辨率、实际限帧/刷新率 |
| 电源 | 是否拔电、电池电量区间、电池温度、环境温度、省电设置 |
| 负载 | 固定页面/项目，滚动、输入、切换与导航的次数和操作顺序 |
| 缓存/网络 | 冷/热启动、页面缓存状态、是否在线以及网络是否一致 |
| 测量 | 传感器路径、单位、正负号含义、采样频率、暖机和统计时段 |

建议暖机约 5 分钟，每段固定负载采样 10–15 分钟，至少三次交替测试。时长属于测试建议；不足以单独证明全天稳定或实际续航。

## 负载组合

1. 桌面空闲：确定基本功耗和残留后台进程。
2. 同网页连续滚动：检查合成、rasterization 和 Present。
3. 同编辑器项目输入/滚动：代表日常交互；候选框与菜单需保持正确。
4. 连续导航 50 次以上并记录帧时间：覆盖历史约 30 次后的退化线索。
5. 30–60 分钟混合操作与休眠/恢复：检查长时退化、GPU 进程重建和会话清理。

视频播放单独测量，并同时记录是否使用硬解；不能混入图形渲染结果里。

## 数据与报告

可使用 [CSV 模板](../evidence/benchmark-template.csv)。文件只有表头，没有虚构测试结果。

若用电池电压/电流估算功耗，先查明实际节点单位和符号。两者都以微单位报告时，功率幅值为 `abs(current_uA * voltage_uV) / 10^12` W；插电时电池电流不能直接代表整机耗电。建议同时保存原始样本、平均值、中位数、波动区间、温度和 GPU 重建次数。

续航结论需要电池能量消耗或足够长的同负载放电记录，注明测试条件。峰值、单个瞬时样本和不同亮度下的数字只作为观察。
