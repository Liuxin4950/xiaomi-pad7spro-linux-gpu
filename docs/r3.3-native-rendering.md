# r3.3 原生 GPU 渲染交付

2026-10-12 已安装到 `/opt/pad7spro-gpu-observe-20261012`，统一 `gpu-run` / 桌面入口默认采用 r3.3。原厂 Mali 驱动保留，r2 / r3.2 的历史证据保留。

## 实际实现

Chromium/Electron 的二维光栅化与合成改为 **Skia → 原生 Vulkan → Mali**，运行时后端为 `GaneshVulkan`。WebGL 保持 ANGLE Vulkan；OpenGL 应用仍走 Zink，WebKit 仍走原有硬件适配。不是将所有图形都绕过 ANGLE，也不是替换原厂驱动。

启动器合并已有 `--enable-features`，保留应用特性，并拒绝原生模式下禁用 Vulkan 或选择 SwiftShader 的矛盾参数。`PAD_GPU_SKIA_BACKEND=angle gpu-run ...` 可回到原来的硬件二维路径；不自动回退软件。

保留 r3.2 的 Copy 命令复用、空闲休眠、Complete/Idle 顺序修复和固定节奏的 60 fps 上限。Termux:X11 显示前端已启用 GPU Copy 与屏幕绘制的合并处理；APK Java/资源保留输入修正，签名一致。最终核对时，新 X server PID 19652 已映射经 SHA-256 核对的当前 APK，启动参数为 `-max-fps 60`；显示时钟门控代码已加载，WSI 上限同时保留。这里没有将启动上限当成屏幕实际呈现帧率。

输入法接口现在明确不提供 Linux 编辑器不存在的真实光标几何信息，避免虚构的 `CursorAnchorInfo` 被反复回调。文本、组合输入、selection 与按键函数保持原实现。此前仅修复取消监控仍会在前端重连后触发搜狗 CPU 忙循环；本次拒绝不可用的几何接口后，搜狗相同 PID 9163 最后连续八个一秒样本均为 0 CPU 时间。没有改 HyperCeiler 设置、冻结或禁用系统服务。真实中文输入与候选框的人工交互仍需使用中确认。

## 最终运行核对

同一 1280×800 文本滚动页面、同一 Mali / WSI，两个窗口在各自观察段保持可见；初次窗口被遮挡的样本已弃用。

| 指标 | 原二维路径 | 原生 Vulkan 二维路径 |
|---|---:|---:|
| 实际 Skia 后端 | GaneshGL | GaneshVulkan |
| 页面 rAF 频率 | 35.83 /s | 58.86 /s |
| 浏览器 CPU / 页面帧 | 10.43 ms | 8.39 ms |
| 同窗口时间的浏览器 CPU | 1.21 s | 1.61 s |
| GPU 崩溃次数 | 0 | 0 |

每页面帧 CPU 开销下降约 **19.6%**，同时生成更多帧。每秒 CPU 绝对值上升，因为画面产量更高，不能谎称这个场景 CPU 总量下降。rAF 不是屏幕扫描或实际新内容呈现 FPS；这里证明应用产帧与单位工作效率，不直接证明屏幕每秒 59 张新画面。

两种路径 WebGL 都实际使用 Mali-G925，回读颜色为 `[26,153,204,255]`、错误码 0。Trae 独立实例也确认 `GaneshVulkan`、Vulkan enabled、Mali、0 GPU 崩溃。29 项启动器检查通过。Vulkan/WSI 的原有生命周期回归保留。

## 当前会话与界限

当前桌面和 ChatGPT 已重开。最终核对的主进程 PID 20072 含 `--enable-features=Vulkan --use-vulkan=native`，GPU PID 20126 映射当前 WSI 和 Mali、GPU 崩溃计数 0。此前独立 Chromium/Trae 实例确认 GaneshVulkan；此轮没有额外读取 ChatGPT 的运行时 Skia 名称。应用配置和登录数据保留。

首次自动启动尝试曾因 chroot 早期缺少 `/dev/fd` 而启动失败，后来当前会话已正常启动。本次同时移除启动器环境清理对该路径的依赖，并同步安装文件和校验清单，避免下一次启动重现。Android 三个启动脚本的设备文件与仓库参考文件逐字节一致，UID/GID 10305、权限 0700；见入口证据。

仍有 AHB Copy 和 Android 显示合成，不能称零拷贝。前端刚重连会带来启动和输入法负载，原生批处理前后短功率数据不具备隔离变量条件，未用于宣传省电幅度。此前静止窗口放电约 3.35 W 的读数也不等于长期续航验收。锁屏恢复、整机电量/热量对照、屏幕呈现尾延迟和实际中文输入尚有验证边界。
