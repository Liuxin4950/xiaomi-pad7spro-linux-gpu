## r3.5 的实际新增代码

[WSI 0010](../patches/wsi/0010-downstream-present-regions.patch) 用固定 32 槽记录成功 payload 的变化提示。X11 提交时合并上一次下游提交之后的变化，包含被 MAILBOX 跳过的 payload；未来 payload 的变化不会被旧帧清除。历史不足、未知/空提示、越界及无法编码的坐标都恢复完整更新。每个 swapchain 只创建一个 XFixes region，Present 已在服务器复制该 region 后才能处理下一次修改。

[X11 0005](../patches/termux-x11/0005-present-damage-repair.patch) 比较 Xorg 已有的 drawable serial 与目标 pixmap：位置、可见 clip、redirection 或目标资源变化时丢弃局部 hint，恢复完整内容后仍按兄弟窗口裁剪，保持菜单/IME 遮挡。失败/跳过的 Copy 清除 consumer 历史。只有新服务器公布能力位 8 时，WSI 才启用区域传递；旧 APK 安全保留完整 X11 Copy。协议 `[1,60,15]` 不代表实际屏幕 60 张新内容。

renderer 将一个 entry 内最多 16 个矩形组织为固定栈上的三角形顶点，复用已有纹理/FBO，只发一次绘制。Copy 使用最近邻保持 texel 字节语义；桌面 zoom/filtering 继续使用用户设置。没有丢弃 GPU 工作、删除 fence、引入无限缓存或重写 X Server。

## 已取得的必要验证

r3.5 BUILD_OK / INSTALL_OK；WSI 开/关命令复用均通过。新增独立 consumer 像素 oracle 对实际 X11 region 写入第二张目标图，覆盖轮换 AHB、空列表整帧、跳过 payload、未来帧历史保留、历史溢出和非法坐标；不能只靠源 AHB 正确判断最终更新正确。四 ABI 各 13 个原生单元重新编译/链接，整个 Present archive 使用同一新私有头，顶层及嵌套补丁与真实编译输入匹配。APK 仅改变四个 native 库，证书与 16KiB 对齐正确，原 APK 保存。

此前像素检查在前后台切换 0.6 秒后就截图，捕获了缩放过渡：蓝块为 63×94。稳定版本等 2.5 秒后为预期 64×96，49152 像素错误 0。新验收等待过渡结束，保留原来的逐像素标准与所有失败历史值，不放宽容差。

Mali/AHB 前置探针通过。现有 probe 增加 `--ahb-formats`：同一 Mali 上 RGBA8 linear/optimal color attachment external query 均成功，BGRA8 两种 tiling 均返回 `VK_ERROR_FORMAT_NOT_SUPPORTED`。失败查询的其余字段不作为有效能力。保持应用 BGRA 契约需要现有格式适配；仅有 external-memory 扩展不能证明格式/layout/consumer 兼容，见 [Khronos AHB 规范](https://docs.vulkan.org/refpages/latest/refpages/source/VK_ANDROID_external_memory_android_hardware_buffer.html)。没有为版本号强行删除 Copy。

## 集中验收与剩余边界

按已取得的保存工作/正常重开授权，通过 Android 侧有限 worker 集中执行：原 APK/候选 APK 各一个空闲段、两个物理窗口及前后台恢复、重建/resize、Chromium/Trae renderer、一次局部 Copy trace、三轮交替 r3.3 / candidate timer / candidate auto。失败恢复原 APK、r3.4.1 链接和助手，私人 profile 保留原用途。

功耗、输入延迟及长期温升没有可靠数据时保持未知。人工中文输入/候选框、触控与锁屏、面板模式切换、较长持续工作仍需完成。版本是实现与集成阶段，不能由构建成功宣布全部功能成熟。独立 r3.4.3 用 0001–0009；r3.5 增加 0010，方便判断显示与区域复制各自影响。

回退：单应用 `PAD_GPU_PRESENT_CLOCK=timer` 保持硬件路径；完整退回 r3.4.1 或 r3.3 并正常重开；APK 恢复保存的 original.apk。三类 Termux 启动脚本已统一追随 gpu-run，本轮无须再改写 Zink 库路径。

## 回退后的定向诊断

首轮集成在区域窗口失败，稳定原 APK/r3.4.1 已恢复。像素报告的 42135 差异包括根据仅一个精确蓝色像素推导出的错误窗口原点，不能把该数直接解释为这么多真实损坏像素。实际蓝块形状保留，但颜色存在变化；需定位是 source、Copy destination、Surface 还是 Android 合成阶段。

关屏期间已使用原厂 Mali 的普通纹理、AHB 和 3200×2054 AHB 目标离屏读回，三个场景各 8 种 strip/triangles、精度/dither 组合，均零颜色错误；不能据此证明实际桌面最终呈现正确。诊断 APK 只增加临时 Copy/Surface 单像素定位，待亮屏且解锁后比较区域/完整复制两个场景，随后恢复稳定 APK。没有放宽原逐像素标准或宣布 r3.5 完成。

首轮空闲 Xserver 进程 CPU 1.42→0.00 秒（各约 8.7 秒），主线程 wake 事件 1734→16；不同 APK、短样本并含 trace 开销，仅作为按需调度的初步证据，后者不是全进程线程唤醒总量，也不能作为整机省电结论。原始结果完整保留。

## 前台恢复与 Surface 队列修正

边界读回证明局部 Copy 的 source/destination 和提交前 Surface 受控样本正确；恢复操作期间没有观察到新提交，直至测试窗口退出。不能将退出后背景纹理的颜色变化解释为 Copy 损坏。0006 为 onResume/重新获焦调用既有 viewport 刷新，native 配置变化通过既有 GPU 完成通知唤醒服务器，再由按需 Choreographer 提交当前内容；不添加周期性保活。

同一补丁移除每次 Swap 后对下一缓冲的一像素预热 Clear/fence，保留共享根纹理 Copy/read ownership fence；销毁 Surface 时先解绑再销毁，不再将未完整绘制的下一缓冲送入队列。后者在旧源码中已明确标注会造成窗口重建闪烁。Java/资源已通过离线 Gradle 重建，四 ABI 使用同一新原生源码；APK versionName 标为 gpu-r3.5，versionCode/minSdk/targetSdk/签名保持回退兼容。完整效果仍需集中验收，旧失败数据不改写。

WSI 0011 增加临时 SKIP 后的协作时钟恢复：仅在收到成功 Copy/Flip Complete 且所有旧 timer 请求已排空时恢复；明确 timer、更低上限和旧 APK 不被覆盖。开/关命令复用回归均通过，避免恢复后长期保留双重节拍。
