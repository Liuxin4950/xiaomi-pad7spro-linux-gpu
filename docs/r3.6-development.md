# r3.6 研发与交付要求

用户目标：研究设计并推进到 3.6，确保有明显的性能、适配、能效或功能更新。此目标已重新授权研发；r3.5 最终版继续作为已部署、可回退基线。这里的候选路线不等于已完成的更新。

## 发布条件

r3.6 必须有至少一项实际收益，并完成对应的真实设备验收。仅改版本号、修补错误返回、增加诊断工具、通过构建/mock 或加载 Mali 库，均不足以发布。

可以满足目标的收益：

- 适配：此前不能稳定使用 GPU 的实际应用，具备可持续使用的硬件绘制路径，中文、输入法、选择、缩放、窗口变化和退出行为正常；不得把自动 raster 回退当成硬件适配。
- 性能：同负载交替对照的中位数/尾部指标有可重复改善，幅度超过测量波动，并且实际交互正确；需明确测的是应用工作、WSI 提交、Surface 呈现还是物理内容。
- 能效：保持相当体验与工作量，多个匹配负载区间的 CPU/GPU 工作或整机能量有可重复降低；降低工作量、改变亮度或关闭用户应用不算同条件收益。设备电池数据只能描述整机。
- 功能：交付原来缺少、日常可使用的新功能，完成实际操作与恢复验收，并给出开关/回退范围。

发布时必须保留 r3.5 原始证据、生产前缀及 APK 备份；候选、已安装、运行中映射分别记录。图形入口继续经 gpu-run，不全局切软件，不改原厂 Mali、系统服务、SELinux。涉及 APK 或会话切换，完成候选和备份后通知用户，由用户安排重启。

## 优先路线与停止条件

### A. Writer / LibreOffice 真正的 GPU 文档适配

已有直接证据：临时共享上下文传入 drawable None，进入交换链和 Present 注册。WSI 防御候选已解决错误传播问题，但没有完成应用适配。继续检查与已安装 LibreOffice 25.2.3 相匹配的 Skia 源码和补丁；正确的无窗口共享 context 不应创建窗口交换链。

先在私有 profile、自建文档、独立进程中验证正确实现。未通过实际窗口稳定性不改日常入口；若只能通过脆弱二进制偏移或替换成任意窗口绕过，拒绝推广。验证通过后比较相同文档、缩放、窗口尺寸、后台负载的滚动与编辑。

### B. 独立光标图层

上游 Termux:X11 PR 1085 当前 open，2026-11-03 更新，锁定研究 commit `bbb256c143bc3cda8f450cb5efe0e88428c9aabf`。它将光标位置交给 SurfaceControl 子层，在不需要平移桌面裁剪时跳过整帧 GL 绘制。这是实现意图，尚不是本机节能/延迟证据。

在 r3.5 全部 14 个补丁之后评估移植；必须保留精确裁剪、copy ACK/ownership fence、显示许可、增量 Damage、Surface 重建与按需空闲语义。构建和离线验证后才准备 APK。实际验收覆盖光标形状/热点、隐藏、窗口缩放/旋转/后台恢复、桌面平移、输入法弹窗、拖拽与光标纯移动时的主 Surface 工作量。不得把新增图层呈现率当作桌面新内容 FPS。

如果独立图层创建失败，允许回到原来的硬件 GL 光标路径；这不等于软件渲染回退。不增加默认高频定时唤醒。

### C. OS4 会话融合与能耗基线

保留今天已验证的 Provider 配置和会话观察修补，但自然锁屏、跨高 CPU 策略检查、夜间/重启恢复仍需新证据。先被动观察，不循环覆写省电名单，不新增常驻解冻器。

性能/能耗对照先记录应用后台负载、显示状态、温度与内存回收；无法匹配的样本标为无效，不通过反复扩大测试掩盖没有收益。A/B 路线有一项达到交付标准即可形成版本实质，不要求为了凑版本同时修改所有层。

## 2026-11-11：独立光标的首轮实机行为验收

当前候选 APK 与 frontend native 哈希再次从进程实际映射的 backing inode 读取，与已安装候选完全一致。X server 仍为原 r3.5 进程；通过 `/proc/PID/map_files` 读取仍映射的 deleted APK，完整哈希确认为 r3.5，再校验 native SHA、ZIP 映射偏移与内存 ELF 头。新增 inode/device 校验，不因换包而放松固定偏移版本保护。

新增 `src/probe-cursor-overlay.c`：45 秒有界、无输入抓取和无焦点抢占的自有全屏测试窗口。只在窗口内移动指针、切换自定义 24×24/48×16 光标、隐藏/显示；正常退出、EOF 或信号清理时恢复原指针位置和画面。XFixes 版本协商在操作前完成；X 错误走清理路径并返回失败。没有重启桌面、改合成器或写共享内存。

`scripts/verify-cursor-overlay.py`以只读计数器采样配合 Android 物理截图，并读回 X11 指针坐标。`scripts/analyze-cursor-overlay.py` 独立重新计算截图的颜色掩码、形状尺寸、热点、位置、旧形状残留与隐藏结果，核对采样中有移动且主画面绘制没有增加。Android 色彩管理后红色并非原始 RGB(255,0,0)，所以采用隔离背景下的颜色阈值，同时严格核对完整矩形面积、尺寸和坐标。

正式有效样本：本机私有 `build/r3.6-cursor-acceptance-verified-20261111/`，公共摘要与各文件哈希为 `evidence/r3.6-cursor-runtime-2026-11-11.json`。

## 2026-11-11 启动闪退修复（r3.6-final 包）

00:30 安装的 r3.6-final-20261111 APK 每次打开 Termux:X11 都 SIGSEGV。tombstone 稳定为
`Renderer::computeCursorOverlayRect()+4` ← `resendCursorOverlayBuffer()+64` ←
`threadLoop()+636`，fault addr 0x594，空指针读。

根因：00:29 的 finalize 改动把 `computeCursorOverlayRect()` 移到
`resendCursorOverlayBuffer()` 开头。该函数会从 `refreshContext()` →
`ensureCursorOverlay()` 到达——这是 Activity Surface 创建时，X server 尚未共享
state，`state == nullptr`；`computeCursorOverlayRect` 无条件读
`state->cursor.width`（共享状态内偏移 0x594）导致必现崩溃。23:40 的候选包没有这行，
所以只在 final 包出现。

修复（最小改动）：`resendCursorOverlayBuffer()` 先判 `state` 与
`cursorOverlayRenderTarget` 再计算几何；`computeCursorOverlayRect()` 增加
`if (!state) return false` 防御。重编 native → 重新打包 → 安装（用户此前已授权
“如果没有问题就安装”）。

- APK：`build/r3.6-release-20261111/termux-x11-r3.6-final-fixed.apk`，SHA-256

  属预期，不是崩溃。

  `previous-installed-candidate.apk`（d237fa10…），r3.5 生产备份仍在

### 本轮实机反馈与第二输入候选

第一包安装后用户明确反馈“有一定的改善，但是快速移动还是老卡了，全是瞬移”，因此第一包不能判为解决。第一包 60 秒实际采样中捕获 event15 相对移动 3757 个报告、X 坐标变化 3574 次、overlay 几何变化 3293 次；这些跨整段的计数不等于物理 FPS，也没有建立端到端逐事件归因。每秒至少30个移动报告的区间中还包含停手，长间隔不能全部算成系统掉帧。20秒 Perfetto 的16MB环形缓冲仅保留12.77秒，该段5个 cursor layer快照位置均相同，未覆盖用户快速移动；不可拿回调间隔推导快速移动的显示性能。

追加 Java 端最小修复：原有 `requestUnbufferedDispatch(MotionEvent)` 只在 ACTION_DOWN 触发，未覆盖悬停鼠标。Android API30+ 对 LorieView 及其父视图请求 POINTER/TRACKBALL source classes 直接分发，官方接口说明见 https://developer.android.com/reference/android/view/View#requestUnbufferedDispatch(int) 。补丁 `patches/candidates/termux-x11-mouse-unbuffered-input.patch`，native 与第一包相同，Java/Gradle构建通过，签名/对齐和内嵌native一致性通过。

### 相对捕获实际生效与采样

系统回读 `Pointer Capture: RELATIVE, seq=1`。首轮relative-fast-v4在用户点击前结束，未捕获移动，保留为无效样本；随后relative-fast-v5取得60秒实际移动，5543个相对报告、5367次X坐标变化、5392次overlay几何变化。按每秒至少30个报告划出的活动区间，内核报告间隔P50/P95/P99为8.745/13.826/18.525ms，X坐标变化间隔为8.665/15.359/20.452ms，overlay为8.516/17.123/21.532ms。这些区间仍可能包含停手和触边，不把所有长间隔当作系统停顿；两个输入模式的动作不同，不能声称严格A/B性能百分比。

去除大体积layers snapshot后，本轮12秒跟踪完整保留约11.993秒，LorieCursor回调1208次。回调、SF present调用、FrameTimeline及Scene浮窗计数不同，不能把任一个替代物理唯一内容FPS。跨内存快照与trace时间戳检查“on-demand callback睡醒漏一帧”假设，没有找到>12.5ms回调间隔内、前7.5ms已发布新几何的样本，因此未据此继续改调度或换包。

相对捕获已真实生效，但用户只反馈“怀疑是帧率不够”，没有明确确认该模式消除瞬移；不记为用户验收通过。目前保留可随时恢复false的输入偏好，APK仍为5aed7953…，本轮未再安装。
