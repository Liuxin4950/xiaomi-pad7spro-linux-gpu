# 已知问题

| 问题 | 当前状态 | 处理/验证方向 |
|---|---|---|
| 连续导航约 30 次后 `AllocateRingBuffer() failed` 或帧时间恶化 | 历史已出现；根因与当前是否仍复现未确认 | 按固定版本连续导航、记录日志/帧时间和进程重建 |
| 视频 Decode/Encode 显示 Software only | 图形 GPU 路径不等于硬解；尚未接通 | 视频负载单独验证 |
| ChatGPT 在线内容超时 | 曾影响内容级验证 | 先区分网络/服务请求与图形问题 |
| CC Switch GPU 路径失败 | WebKitGTK/Tauri 当前仍用 CPU；历史 Zink 尝试段错误 | 单独适配渲染框架，不使用 Electron 参数 |
| 上游 X11 GPU fast path 覆盖菜单/输入法候选框 | 作者设备使用本项目裁剪补丁后已解决 | 保留弹出层、遮挡、滚动和 redirected pixmap 回归场景 |
| 文档 60 FPS 与设备快照 120 FPS 不一致 | 本草稿参考默认整理为 60；设备未被修改 | 部署/录制时核对实际命令行与 Present 频率 |
| 桥接目录依赖混合 | 应用入口同时依赖主基线和 canary | 首版锁定完整组件，不能漏发主基线依赖 |
| 脚本使用 root、禁用 Chromium sandbox | 当前配置限制 | 普通用户/sandbox 支持作为独立适配任务 |
| 其他设备、固件和应用 | 未验证 | 提供固定版本与复现证据后扩展支持表 |

输入法/菜单修复、60 FPS 与应用 GPU 渲染均有既有记录，但不代表历史长期问题已全部解决。每次更换驱动、WSI、libhybris、X11 或应用版本后，都应按验证文档重新记录结果。

新栈的实例销毁非法指针问题已修复并重复验证；显式绑定现有 binderfs 是 AHB 验证的必要条件。当前仍未完成新栈窗口、APK和功耗验收，见 [最新验证状态](development-status.md)。
